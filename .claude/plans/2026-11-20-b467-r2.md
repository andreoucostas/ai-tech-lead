**Scoring, fixed now.** The grader reads the parent's final merged findings (the `/review` report after Step 4's merge).
Dk is found when one row names Dk's file stem (`CheckoutController` or `EventRegistryTests`, no `.cs` required: last time a
`.cs`-anchored pattern missed `CheckoutController.Refund`) and matches Dk's case-insensitive pattern: D1 `interpolat|structured|
message template`; D2 `System\.Text` and `unused|remove`; D3 `authorization|bearer|token|credential` and `log`; D4 `NotNull|
tautolog|freshly|construct`; D5 `InvoiceIssued|InlineData|weaken|(remov|delet|drop)\w*.{0,40}(case|row|data)`; D6 `switch|
open.?closed|OCP|polymorph|third arm`; D7 `catch|swallow`; D8 a row naming `DEBT-006`. A row may count for several Dk; that
is reported. Every row is also read by hand; a hand-read that disagrees with the grader is reported, and if it changes a
reading the result is unreadable. Rows matching no Dk are counted as other findings, reported, not scored. Owner attribution,
when the report shows it, is reported, not scored.

**Runs, budget, order.** Calibration C0 (arm K, uncounted), then n = 5 per arm in the order K O O K K O O K K O.
Parent `--model sonnet`; reviewers as `review.md`'s reviewer-model rule sets them (the three Haiku reviewers on Haiku).
`--max-budget-usd 1.00` per run: recorded review-only passes cost 0.49 to 0.66 USD ("B-467 results", six attempts; pilots

**Validity (each run, before any scoring).** Valid only if: the terminal result is success, not a budget or usage-limit
error; the final message holds the merged findings and a verdict; all six reviewers were dispatched and each returned a
message (none may be missing: every reviewer owns a scored defect, and the parent's dispatch is not what the arms vary); no
reviewer or parent reply says CANNOT EXAMINE; the permission log shows no denied call by the parent or a reviewer. An invalid
run is excluded and may be repeated once, inside the stop rule; never past it.

**Stop rules.** Check the first row before any further run: host version, parent model family, reviewer models, the budget
flag, the arm's patch commit present (O) or absent (K), and `git status` showing the subject alone. A run cut by its budget
is an error, not a score. Stop at 12 USD whatever is left. A second invalid run in a row for one harness cause stops the
measurement for a runner fix and a re-registration.

**Readings.** found(run) = number of D1-D8 found; mean per arm over valid runs.
- **Unreadable** if either arm has fewer than **N = 4** valid runs (with three or fewer, one run's swing, 8 to 12 of 12
  across last time's six attempts, is as large as the margin being judged), or C0 finds fewer than **M = 5** of 8 (below that the subject cannot
  show a loss of one or two defects, so the instrument is not seeing what the chain might add). Unreadable: nothing ships,
  B-467 stays open with the result recorded.
- **Ships the cut** if mean(O) >= mean(K) - 1 and no Dk found in every valid K run is missed in every valid O run. Then
  one guarded commit with the candidate, this measurement as its red/green evidence; B-467 closes done.

  run. Between the two (O lower by more than 1, less than 2): the ship test is not met, so the cut does not ship either;

- Reported, not scored: per-defect detections per arm; whether solid-check and test-critic Read the carrier and
  convention-check `AGENTS.md` in O; other findings per arm; verdicts; cost and wall time; first-request context per reviewer.

## Amendment 2, after C0, before any counted run (2026-11-20)

Made after the calibration run C0 and before any counted run; nothing above this heading is changed.

- **What C0 showed.** C0 (arm K, 2026-11-20, runner `671e93f8`) was invalid and is not counted; it cost 0.82 USD. The parent captured
  the review scope twice and ran `dotnet test` between the two captures. The fixture had no `.gitignore`, so about 200 untracked
  `bin/` and `obj/` files made the second capture differ, and the parent ended CANNOT EXAMINE. Five permission denials occurred
  (variable assignments such as `$p=...` and `$b1=...`, and `Format-Table`), each recovered with a literal command, not with `$()`.
  All six reviewers returned and between them named all eight seeded defects. That is NOT a calibration pass, because the run was invalid.
- **Change 1, the fixture.** `Initialize-ReviewSubject` commits a `.gitignore` holding exactly `bin/` and `obj/`, in both arms,
  before the subject is copied in (in arm O after the target-patch commit), so `git status` lists the subject and nothing else even
  after a build.
- **Change 2, the validity rule (approved by the maintainer in chat, 2026-11-20).** A denied permission no longer invalidates a run by
  itself. When the review completed (a verdict, an Issues section, all six reviewers returned, no CANNOT EXAMINE, a successful
  terminal result), the denials are reported in the row as `denials=<n>` with the commands (60 characters each) and the run is valid.
  A denial beside CANNOT EXAMINE, a missing reviewer or no verdict is invalid, and the denial stays listed. A missing permission log
  stays invalid.
- **No new allowed forms in the permission check.** Change 2 removes the need, and new parsing in a security filter is cost and risk
  for little gain.
- **Budget, re-registered by the maintainer (Option 1).** Total 15 USD, of which 0.82 is spent. Per-run cap 1.25 USD (the
  `b467-review` scenario's `budgetUsd` moves from 1.00 to 1.25). Order: C1 (arm K, uncounted), then K O O K K O O K K O. A run starts
  only if spend so far plus 1.25 is at most 15.00. If C1 costs more than 1.00 USD, stop and re-register. C1 must be valid and find
  at least M = 5 of 8 defects.
- Everything else in the plan and Amendment 1 stands: the arms, N = 4, the three readings and the scoring.
