## Question and hypothesis

B-346's one unregistered read found 3 of 6 `/bootstrap` drafts missing a step their own instances contain (an event draft without
the handler's DI registration, two drafts without the test step). B-514's one generation missed none, and on fixture v2 every step
sits in code the session reads three times. Question: when a step lives in a file the session does not read by default, does the
current 3a-bis draft omit it, and does the candidate (check each draft against every instance it lists, using the commit that added
the instance as its file list) stop that without making the drafts worse?

Predictions, written before any run: the current arm omits at least 4 steps over its 8 drafts, mostly the two steps no code
references (`topic`, `deploy`), at most 2 of fixture v2's steps; the candidate omits at most 1, and writes the same drafts.

## Runs

- Host: Claude Code 2.1.312 (recorded per run), `--model sonnet` as B-346 and B-514 ran. Each run, from a shell with every `CLAUDE*`
  and `ANTHROPIC*` variable removed, `DISABLE_AUTOUPDATER=1`, `ATL_SOURCE_CHECK=off`: `claude -p <prompt> --session-id|--resume <id>

  acceptEdits --allowedTools <B-514's 51-rule generation list>`. Call 1 is `/bootstrap`; a further call, `proceed`, only when the
  previous call made no Write, Edit or MultiEdit call; at most three calls. The driver is a scratch script, as B-514's generation was.
- n = 4 per arm (8 drafts each when every run drafts both operations): B-346's rate (3 of 6 drafts) puts about 4 drafts with a miss
  in the current arm, enough to see the candidate halve it; a run cost 1.15 USD in B-514 (up to 8 USD a call if workers start).
- Order: the four current runs first (two at a time), graded; if they omit no step, the candidate is not run (below). Then the four
  candidate runs, two at a time.
- Valid: every call exits 0 with a `success` result and the session entered Phase 3 (an Edit or Write of `AGENTS.md`). An invalid
  run is repeated once after its arm; a second invalid one is reported by its reason, not scored. A quota or rate-limit error stops
  the series: what ran is kept and reported as partial.
- Recorded per run: cost (the last call's `total_cost_usd`, cumulative across `--resume`), `system/init` model and host version,
  duration (summed `duration_ms`), calls, workers started, permission denials.

## Grading (`meta/eval-fixtures/b515-draft-steps/grade.py`, sha256 `5f1bbcef069f…`; the drafts, never the final message)

- How drafts are read: this host refuses writes under `.claude/skills/` in acceptEdits (B-514), so a draft is the last Write payload
  for `.claude/skills/<slug>/SKILL.md` in the run's streams, or the file itself when a write landed. A slug `framework-ownership.json`
  owns is not a draft. No draft is edited.
- Per draft: its operation (P1 when the body names `EventRegistry`, P2 `ReportCatalog`, else a false positive); its listed instances
  (instance names or keys in SKILL.md or its reference; none listed grades against all three); **omitted** = the steps its listed
  instances' files map to that no pattern finds in the SKILL.md body (frontmatter excluded, so a step only the description or only
  the reference names is omitted). Reported apart: v2's steps and the two added ones.
- Per arm: total omitted steps, drafts with an omission, P1 and P2 drafts written, false positives. Secondary, reported only: the
  reference given as a Markdown link (B-346: 4 of 6 were code spans), whether an event draft says an unregistered event is not
  published, the format checks (origin, `DRAFT` prefix, a reference written), cost, duration, workers.
- **Invented steps**, hand-classified: each numbered step of a draft is one of the operation's steps, a framework one (owner check,
  build and test), a read, or invented (a change to a file none of its listed instances touches); the grader's `extraFiles` (files the
  body names outside the instances' files) is the lead. Every invented step is listed in the results.
- Hand check: every `omitted` value is checked against the payload; a disagreement is reported beside the grader's, never silently
  replaced. The grader is shown red before any run: `grade.py --self-test` grades hand-made drafts that omit the DI step and the deploy
  step as `omitted=di` and `omitted=deploy`, and complete ones as nothing.

## Decision rule (valid runs)

- NO-MISS: the current arm omits no step. Stop; the candidate is not run and does not ship; B-515 says this fixture cannot show it.
- SHIP: the candidate's total omitted steps are at most the current arm's minus 2 and at most half of them, and nothing is worse: as
  many P1 and P2 drafts written as the current arm, no more false positives, at most one more invented step, and the format checks
  (origin, `DRAFT` prefix, a reference written) no lower by 2 or more.
- Otherwise NO-SHIP: B-515's status records the counts; `src/` is untouched.
- Not shown: Copilot CLI and VS Code; other models; the angular and monorepo copies (same text, not run); other operation shapes; a
  large repository where the session cannot read every file; interactive use (headless `-p`, `proceed` answers).
