## B-450 · A security finding reaches the team saying neither what it is nor where it is

### Facts

- `src/stacks/dotnet/files/.claude/commands/security-gate.md:64-71` (same in monorepo): an ordinary code finding gets
  a repository-relative `file:line` "only when both the locator and target are safe for every repository reader". That
  is an opt-in with no floor: a finding that fails the safety test is left with nothing, and nothing says what the
  minimum is when it passes.
- Step 6, `security-gate.md:110-135` (dotnet, monorepo): appends "a minimised row" whose `Affected area` is
  "redacted when sensitive". No rule says what an unredacted area holds, no rule assigns the row's ID (the template
  row at `src/core/SECURITY_FINDINGS.md` shows `_`), and the chat verdict never says which row was written or that one
  was not.
- **Angular appends nothing.** `src/stacks/angular/files/.claude/commands/security-gate.md:2` says "It does not append
  findings"; there is no Step 6. B-135 (2026-08-12, `meta/BACKLOG-DONE.md:405-418`) made that description truthful
  instead of adding the step; its record gives no reason Angular should differ. Every distribution ships the register
  (`src/core/SECURITY_FINDINGS.md` is core). An Angular team therefore has its findings only in the chat transcript.
- The auditor's own table already carries `File:line | Risk | Severity | Suggestion`
  (`src/stacks/*/files/.claude/agents/security-auditor.md:85`), so the location exists upstream of the gate.
- Readers of the register: `src/core/.claude/hooks/session-start.ps1:190-210` counts `| Open ` cells and takes the
  **second** `yyyy-mm-dd` on an `Open` line as the due date. Column order and the Status token are load-bearing; a new
  column must go after `Due`, and the two dates must stay the first two on the row.
- Contract test: `src/core/tests/hooks/SecurityReviewContract.Tests.ps1`, with an `$isAngular` branch that asserts the
  no-append text and that Angular "gained no append step" (line 60).

### Direction

1. **Set a floor, keep the redaction list.** Replace the opt-in sentence with: for an ordinary code finding, the verdict
   table names the repository-relative path and line, and the register row's `Affected area` names the path (no line:
   lines move) plus the symbol, route or type when the path alone is ambiguous; `Repository-safe summary` is one
   sentence saying the defect class and the fix class (for example "SQL built by string concatenation in the order
   search; parameterise"). Redaction applies only when the path or that sentence would itself disclose one of the
   classes the existing list names (tenant, customer, host, user or home path, vault or key, secret path, transcript,
   disclosure channel). A redacted row writes `redacted (<class>)` in the area column so a reader knows why, and the
   verdict says the full detail stayed in the chat with the person who ran the gate. The credential-finding rules
   (no echo, no Git mutation, restricted human handling) are untouched.
2. **Say where it went.** The verdict ends with one `Recorded:` line: `Recorded: SF-12, SF-13 in SECURITY_FINDINGS.md`,
   or `Recorded: none (<reason>)` where the reason is one of APPROVE, severity below high, credential finding,
   duplicate of SF-n, legacy schema, or (if decision 1 below keeps it) this distribution records no findings. This is
   the "how will the user find it" half of the report.
3. **Assign the ID.** `SF-<n>`, n one above the highest `SF-` in the active table, `SF-1` for a fresh register. The gate
   reads the table before appending; the Copilot `.agents/skills/security-gate/SKILL.md` wrapper runs the command, so
   it inherits all of this without its own text.
4. **Angular appends too (recommended; maintainer decides).** Add dotnet's Step 6 to the Angular command verbatim, flip
   the description, and move the contract test's `$isAngular` branch to the appending branch. The only reason on
   record for the difference was a false claim; the register is shipped anyway, and a team whose findings live in a
   transcript is this report. If the maintainer keeps no-append, the `Recorded: none` reason in step 2 must say so and
   tell the team to copy the table into the register by hand.
5. Extend `SecurityReviewContract.Tests.ps1`: assert the floor sentence, the `Recorded:` line and the `SF-<n>` rule in
   each appending stack's command; assert the Angular change per decision 4. These assertions are red on the unfixed
   tree; that is the red case for a text-only change.

### Verification

`.claude/hooks/tests/Invoke-HookTests.ps1 -File SecurityReviewContract.Tests.ps1` plus `-File
PowerShellSemantics.Tests.ps1` (its register fixtures at line 131-167 use the legacy six-column header and must stay
green, proving the hook still counts the row), on both hosts. Then the ×3 build, validate and footprint recipe.

row names the file and the symbol, and the verdict ends with the row IDs it wrote or the reason it wrote none. Only a

## B-451 · The committed baseline repeats one evidence row per matched file per claim

### Facts

- `src/core/scripts/bootstrap-baseline.ps1:443-444`: Record writes `evidence <id> <pattern> <path> <blob>` once per
  matched path per pattern per claim. A claim over `src/**/*.cs` lists every C# file; thirty such claims list it thirty
  times. That is the redundancy the report describes.
- Impact (`:545-561`) resolves each pattern against the current tree and compares the `(path, blob)` set with the
  recorded rows for that pattern. `Get-Moves` (`:264-285`) and `Get-Followed` (`:296-306`) key on `path<TAB>blob` pairs
  drawn from those rows. Carry-forward at Record (`:454-474`) copies an unlisted claim's old rows verbatim so that "its
  old evidence hashes keep it affected until a run rechecks and lists it" — the invariant the test at
  `src/core/tests/hooks/BootstrapBaseline.Tests.ps1:320` protects.
- `Get-Areas` (`:181-198`) already stores one 16-hex hash per area, so a set hash per pattern has a precedent in the
  same file.
- Read-State (`:344-396`) refuses any schema but `1` and any unknown row kind.
- The installer never copies a root `.gitattributes` (`src/core/scripts/install.ps1:321-325`), but a `.claude/.gitattributes`
  is not excluded, and 7c85416c already maps a `.gitattributes` name inside a brownfield archive to `_.gitattributes`.

### Direction

1. **Schema 2: one file table, pattern-only evidence rows.** New rows: `file <path> <blob>`, one per path that any
   claim pattern or hazard row matched, sorted ordinally (so a merge conflicts only when two branches touch adjacent
   paths). Evidence rows become `evidence <id> <pattern>` with no path or blob. Absence claims the same. Expected size
   for the reporter's tree: about 1,000 file rows plus a few hundred evidence rows, and the size no longer grows with the
   claim count.
2. **Recover today's per-claim sets by resolving, not storing.** Read-State builds a *recorded snapshot* (`Blobs`,
   `Sorted`, `Joined`) from the file rows; `Resolve-Evidence` run against it yields exactly the `(path, blob)` set the
   schema-1 rows held. `Get-Moves` takes its pairs from the file table plus hazards. Impact and Get-Followed are
   unchanged in logic, only in where the recorded set comes from.
3. **Keep the carry-forward invariant with one marker.** With a shared file table rebuilt from the current tree at
   Record, a carried claim would silently receive current hashes and read as verified. So at Record, for each carried
   claim and pattern, compare its *old* recorded set (resolved from the previous baseline) with the current set; where
   they differ, write `evidence <id> <pattern> stale`, and Impact reports a stale row as `changed-evidence` without
   resolving. The test at `:320` stays green; add its schema-2 twin.
4. **Schema 1 stays readable.** Read-State accepts `schema 1` and synthesises the file table from its evidence rows, so
   a consumer's existing baseline Impacts correctly and the next Record writes schema 2. The three fixtures under
   `meta/eval-fixtures/*/files/.claude/bootstrap-baseline.tsv` are schema 1 and need no re-record.
5. **Diff tooling (second step, after asking the reporter's host).** A shipped `src/core/.claude/.gitattributes` holding
   `bootstrap-baseline.tsv -diff linguist-generated=true` collapses the file on GitHub and hides it from `git diff`
   (`git diff --text` still shows it). The reporter's field hosts on Bitbucket Data Center (B-357's note), which does
   not read `linguist-generated`; confirm what it honours before shipping an attribute for it. A new framework-owned
   file below `.claude/` also needs the brownfield archive case (`UpdateDelivery.Tests.ps1`, the B-430/B-441 shape) and
   a `framework-ownership.json` row. Do step 1 first; step 5 only if the compaction alone does not answer the report.

### Red first

`BootstrapBaseline.Tests.ps1`: (a) two claims over the same glob record each matched file once (today: twice);
(b) a schema-1 baseline still Impacts to the same lines; (c) the stale marker: a carried claim whose evidence changed
before the record is reported by the next Impact. The 35 existing cases stay green on both hosts, plus one CP437 leg.

### Docs and CHANGELOG

`bootstrap.md` 3f and `rebootstrap.md` describe the file only as "a baseline"; the 0.90.0 CHANGELOG sentence ("a content
hash of your files and, for each convention written to AGENTS.md, the files that convention rests on") stays true.
Consumer's voice: "The baseline lists each file once and each convention's evidence as the pattern it rests on, so
it is a fraction of its former size and a merge conflicts only where two branches touch neighbouring files. Your
existing baseline is read as before and rewritten in the new shape by the next `/bootstrap` or `/rebootstrap`."

## B-452 · Decide whether the baseline stays committed; say that drift is by design

### Facts

- It is committed on purpose: `src/stacks/dotnet/files/CHANGELOG.md:644-660` (0.90.0) says "commit it with the other
  artifacts", and `bootstrap.md:451` says "commit" after `WROTE`. The reason is nowhere stated for the consumer.
- The script hashes the working tree with `git hash-object --stdin-paths` (`bootstrap-baseline.ps1:171`), which applies
  the clean filter (end-of-line conversion) for each path. For a file whose index blob already holds CRLF and no `text`
  attribute, a machine with `core.autocrlf=true` hashes the cleaned bytes, which differ from the index blob; a machine
  with `false` hashes the index bytes. Two teammates can therefore record different hashes for an unchanged file. That
  is the "couples to current line endings" half of the report, and it is a reasoned claim, not yet observed.

### Direction

1. **Record the decision** as a WSD in `meta/workspace-decisions.md` (at most ten lines, one index line in
   `meta/decisions-index.md`): the baseline is a committed artifact because it records the state the last analysis saw,
   for every clone; a drift report after an unrelated PR is the mechanism working. Rejected: an ignored local file
   (every teammate's first `/rebootstrap` runs in full, and a fresh clone can never `RESULT stop`); CI generation (the
   baseline is the *output* of an analysis the agent ran, with a claims file, not a function of the tree).
2. **Say it where the team reads it.** One sentence in `rebootstrap.md`'s pre-step (×3 stacks) after the Impact
   command: "The baseline is meant to be committed and to change whenever source changes; a drift report after an
   unrelated change is the mechanism working, and `RESULT stop` is the no-drift case." One clause in
   `docs/reference.md:88`'s row. The CHANGELOG entry in the consumer's voice repeats the sentence and says what is
   *not* a signal: the hash rows themselves are not for review.
3. **Settle the line-ending half with a test, then fix only if red.** `BootstrapBaseline.Tests.ps1` case: commit a file
   with CRLF bytes and no `.gitattributes`, record under `core.autocrlf=false`, then run Impact in the same tree under
   `-c core.autocrlf=true` (the fixture's `G` helper passes `-c`). Expect `RESULT stop`. If it is red, the fix is to take
   a tracked, unmodified file's blob from the index (`git ls-files -s -z`, which is what Git itself compares against)
   and `hash-object` only paths `git status --porcelain -z` reports modified or untracked; `--no-filters` is wrong
   (it would make on-disk CRLF/LF differences count). If it is green, record "not reproduced" in the WSD and leave the
   script alone.

### Tier

Ordinary (meta records, consumer docs, one test; the script changes only if step 3 is red). Gates: the three meta gates
for `meta/*.md`, the ×3 recipe for the stack files, the test file on both hosts.

## B-453 · The baseline records a zero-byte source file as evidence without saying so

### Facts

- `Resolve-Evidence` (`bootstrap-baseline.ps1:221-233`) returns every path a glob matches; Record writes a row for each
  (`:444`). A 0-byte file hashes to the empty blob `e69de29bb2d1d6434b8b29ae775ad8c2e48c5391`, which is what the reporter
  saw. An empty file cannot evidence a convention.
- "Known-debt files" in the same list are not a defect: a convention rests on the files that exist, debt or not. Say so
  in the CHANGELOG sentence.

### Direction

1. **Empty files evidence nothing.** In Record and Impact alike, `Resolve-Evidence` drops a path whose blob is the empty
   blob (both modes must agree, or Impact's recorded-versus-found count mismatch would report `changed-evidence` for
   nothing). They stay in `Get-Areas`, so a file that later gains content changes its area and, now matching, marks the
   claim `changed-evidence`: the right answer. A pattern whose only matches are empty is a no-match (INVALID for a
   scoped or universal claim, as today for a glob that matches nothing).
2. **Name them.** Record prints `EMPTY <path>` once per dropped path (sorted) before the `RECORDED` line.
3. **Route them.** `bootstrap.md` 3f and `rebootstrap.md` 3d (×3 stacks): each `EMPTY` line becomes a `TECH_DEBT.md`
   row (a zero-byte source file: delete it or give it content) unless the register already names the path; the 3f/3d
   report quotes the lines. Nothing is deleted by the framework.

### Red first

`BootstrapBaseline.Tests.ps1`: fixture adds an empty `src/Orders/Api/Controllers/Empty.cs`; Record prints
`EMPTY src/Orders/Api/Controllers/Empty.cs` and the baseline holds no row for it (today it holds one with the empty
blob); Impact after the file gains a class reports the `*.cs` universal claim `changed-evidence`. Both hosts, CP437 leg.
Ordinary tier; after B-451, the check lives in the schema-2 resolver.

## B-454 · An update that starts ignoring `.claude/ai-audit.log` leaves a tracked copy tracked and says nothing

### Facts

- The ignore shipped in 0.86.6 (`src/stacks/dotnet/files/CHANGELOG.md:913`, "for an already tracked log, follow the
  checklist"). `docs/upgrade-checklist.md:85-91` has the recipe (`git rm --cached -- .claude/ai-audit.log`) and already
  says an old header's "keep it in version control" is superseded. The team did not find it; they found the ignore
  line and asked.
- `src/core/scripts/install.ps1:334-336`: the log is copy-if-absent. `:2484-2497`: the hidden-files WARNING excludes it
  on purpose ("ignored on purpose, per-machine state"), so the handoff says nothing about it, tracked or not.
- The answer to "is dropping it acceptable for audit expectations" already exists in the shipped docs:
  `docs/reference.md:73` ("telemetry, not compliance evidence"), `docs/enforcement-surfaces.md:135` ("mutable and
  incomplete; diagnostic telemetry"). The install is the moment to say it.
- Existing shapes to copy: `Get-IgnoredShippedPaths` (`:1984-2000`) for the Git guards (git present, no `GIT_*`
  routing, inside a work tree, exit codes 0 or 1); B-313's WARNING and its test
  (`.claude/hooks/tests/UpdateDelivery.Tests.ps1:1266`); the `:(icase,literal)` pathspec the status reads use since
  7c85416c; B-430's `CANT-VERIFY` line when Git cannot answer.

### Direction

1. **Ask Git once.** After `Get-IgnoredShippedPaths`, on update and brownfield alike: `git --no-optional-locks -C <tgt>
   ls-files -z --cached -- ':(icase,literal).claude/ai-audit.log'` under the same guards. If it prints the path, add to
   the handoff: `NOTICE: Git tracks .claude/ai-audit.log, which this release ignores (.claude/.gitignore). It is local
   hook telemetry, not compliance evidence, and every developer's copy differs. Untrack it with  git rm --cached --
   .claude/ai-audit.log  and commit that with the copied files; your local file stays. An older CLAUDE.md that said to
   keep it in version control is superseded.` If Git cannot answer, one `CANT-VERIFY` line naming the path, not
   silence. Greenfield skips the query (nothing is tracked yet).
2. **Nothing else moves.** The installer does not untrack (it never runs a Git command that changes the index or the
   history; B-135 applied the same no-automatic-mutation rule to the findings register); the copy-if-absent policy
   stays; the checklist step stays and the NOTICE points at it by name.
3. **Doctor:** `framework-doctor.ps1:612-620` reports the log missing or not appendable; add no tracking check there
   (the install is the one moment the team is reading, and a doctor row would nag on every run until the commit).

### Red first

`UpdateDelivery.Tests.ps1`, guarded shape: an update target (`New-B194UpdateTarget` + `Initialize-B194GitTarget`) with
`.claude/ai-audit.log` committed → the NOTICE regex matches and names the `git rm --cached` command; the same target
with the log untracked → no NOTICE; a target with Git routed away (`GIT_DIR` set, as the B-430 cases do) → the
`CANT-VERIFY` line. Red on the unfixed tree: the NOTICE is absent. Both hosts, CP437 leg, `assert-red-first.ps1`, and
step 4 (maintainer reads the diff, or a fresh session attacks it: the attack to try is a tracked log at
`.CLAUDE/AI-AUDIT.LOG` on a case-insensitive checkout, and a log that is tracked *and* skip-worktree).

### CHANGELOG, consumer's voice

"If Git still tracks `.claude/ai-audit.log` from an older install, the update now tells you, gives the one command
that untracks it, and says why dropping it is safe: the log is per-developer hook telemetry that was never a complete
or tamper-evident record, so it cannot serve as audit evidence; your Git history and the findings register are the
records." That paragraph is the answer to the team's question 5.

## B-455 · Decide whether the framework needs a semantic repository index

### Facts

- What ships: `AGENTS.md > Repository Structure` (directories or projects with roles, entry points, where each kind of
  change goes; `bootstrap.md:208`), `docs/wiki/INDEX.md` (scoped claims, `remember-for-team`), `docs/architecture-
  decisions.md`, `docs/warehouse-map.md` on demand, and `FRAMEWORK-CONTEXT.md > Known Hazard Areas`. No symbol or
  module index.
- Standing decisions: WSD-074 ("discover broadly; capture grounded drafts in existing carriers and measure ordinary
  Copilot outcomes before expanding machinery") and WSD-091 (2026-09-18: knowledge-increment expansion is paused until
  the with/without-framework eval first reports; CP1 and RK1 closed as scoped; "any new attempt requires a fresh
  decision"). A semantic index is a knowledge increment.
- The hosts already index: Claude Code's search tools read the tree on demand; Copilot's workspace index serves
  `@workspace`; neither reads a framework-generated index unless a carrier points at it. A generated index is a second
  committed artifact that goes stale on every change: B-452's complaint, multiplied.

### Direction

1. **Default: answer by decision, no code.** Write the reply as a WSD (ten lines): the framework's bet is scoped,
   verifiable claims (wiki) plus a hand-maintained Repository Structure, not a symbol index; the hosts bring retrieval;
   an index would be a stale committed artifact; WSD-091 governs until FS2 reports. Close B-455 with one line in
   `meta/BACKLOG-DONE.md` and one sentence in `docs/reference.md` or `docs/getting-started.md` saying what the framework
   does not ship and what to use instead (the host's search; `/bootstrap` to refresh Repository Structure).
2. **Only if the maintainer wants evidence first (about 3 USD):** one task on the bootstrapped
   `meta/eval-fixtures/b406-orders` fixture that targets code neither the wiki nor Repository Structure names; count
   content-file reads before the first edit, with and without a hand-written `docs/repository-index.md` (module →
   responsibility → entry symbols, under 2 KB) that a one-line `AGENTS.md` pointer names; three runs each on Claude
   Code. Pre-register the threshold (reads halve) at the commit before the runs, as B-414c did. Below threshold, close as
   in step 1. Above it, the next step is a fresh decision superseding WSD-091, not a shipped feature.

### Tier

Ordinary; meta gates for the WSD and backlog, the ×3 recipe only if a consumer doc sentence is added.
