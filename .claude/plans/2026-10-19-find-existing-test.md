## 2. Done when

1. In a repository whose `AGENTS.md` records no test command (no `### Verification Commands` table, or its test row reads `not available`), a bug-fix agent lists the whole tree (not source-extension globs) before it may report tests not available, and runs any existing test entry point it finds. Passes: route-fix fixture → `tests/Test-Calculator.ps1` is run at least once. Fails: `glob **/*.cs` then "no test harness exists".
2. "Existing test entry point" = a committed test project (`*.csproj` referencing `Microsoft.NET.Test.Sdk`/xunit/NUnit/MSTest; an Angular `karma.conf`/`jest.config`/`*.spec.ts` with `ng test`/`jest` in `package.json`); a manifest `test` script (`package.json` `scripts.test`, a Makefile `test` target); a committed consumer-owned script under `tests/`, `test/`, `spec/` or `__tests__/`. Not an entry point: anything `framework-owned/overwritten` or retired (`tests/evals/*`, `scripts/test-weakening-scan.ps1`), generated or dependency folders (`node_modules`, `bin`, `obj`, `dist`), a sample, an eval or benchmark fixture.
3. A recorded command still wins: when the test row names a command, the agent runs that; a found-but-unrecorded entry point is reported as unrecorded test evidence and flagged `/rebootstrap`, never written into `AGENTS.md` by the agent.
4. The run uses the file's evidenced interpreter (`pwsh -File` for `.ps1`, `dotnet test <csproj>`, `npm test`); the agent reads an unrecorded script before running it; it adds no harness, package, test project or file when none is found (decoy: the same fixture without the script → fix, `dotnet build`, "tests not available", zero new files under `tests/`, no `dotnet new`/`add package`/`npm install`).
5. Unchanged: migration/deploy stays manual/CI-only; framework-owned paths are framework evidence only; a saved row naming a framework path still flags `/rebootstrap`; VR #9 and the Bug-fix bullet keep their red-first meaning; the Bug-fix bullet still lists "looks off" (the runner's self-test asserts it).
